# Roadmap Authoring Guide

Use this guide when you need to describe **milestones, deliverables, success criteria, and
dependencies over time**.

This guide is about the planned shape of delivery, not the full project plan in every detail.

## What belongs here

- milestones
- target dates or delivery windows
- what ships in each milestone
- dependencies between milestones
- success criteria

## What does not belong here

- low-level task tracking
- broad goals with no time or delivery framing
- technical implementation checklists

## Core things to capture

- milestone name
- target date or delivery period
- what is expected to be delivered
- what success looks like
- what dependencies or blockers matter

## Core relationships to capture

- milestone -> deliverables
- milestone -> dependency on another milestone
- milestone -> success criteria

## Modus operandi

Use roadmap capture to show meaningful progress:

1. define milestone outcomes
2. identify what delivers those outcomes
3. state target timing
4. state success criteria
5. state dependencies and likely deferrals

## Prompt set

- what is the milestone called?
- what value is delivered in it?
- when is it targeted?
- how will we know it is achieved?
- what must happen first?

## Worked example

- Milestone: Employee Self-Service MVP
- Deliverables: leave request submission, manager approval, dashboard summary
- Success criteria: pilot users can submit and receive leave decisions without manual HR entry

## How this becomes YAML

A technical modeler or AI agent can transform this into milestones with deliverables, status,
dependencies, and success criteria.

## Common mistakes

- naming a milestone without saying what is delivered
- omitting success criteria
- confusing milestone names with project tasks
- forgetting dependencies
